# Controlled application rollback

This prepared path restores retained PHP/HTTPS Nginx digests and the corresponding completed host contract. It never reverses migrations, database rows, uploads or external effects. The operator must establish N/N-1 schema compatibility (expand/contract, retained columns and readable data) before approving `schema_compatible: true`. A breaking migration requires a separate reviewed recovery plan, not this rollback.

The default is disabled: `.github/aws-identities.json` and `.github/aws-deployment.json` remain inactive, `rollback` defaults false, and `ENABLE_EC2_ROLLBACK` must be explicitly enabled by the owner. Reuse the existing protected deployment environment and the separate deployment role. The operation uses the SAME exact approved SSM document ARN, numeric version and SHA-256; `Operation=rollback` selects the embedded hash-bound runner. No new IAM permission is required. Update/reconcile the reviewed Terraform document and activation manifest before first use: adding the recovery runner changes the public contract/document hashes. The workflow rejects missing or different source hashes, mutable images, a recreated environment or unprotected main.

Before dispatch, inspect the private root-owned `/srv/laravel/runtime/releases/state.json` on the selected host through the separately approved operational channel. Do not upload that file, runtime env, keys or command output. Construct the public request using ONLY these fields: `schema_version: 1`, `expected_current` (the completed current release object), `expected_previous` (the completed predecessor object or null), `expected_pending` (the pending release object or null), `target`, `target_contract_sha256`, and `schema_compatible: true`. Each release object contains exactly `source_revision`, `version`, `php_image`, `nginx_image`, `manifest_sha256`, `assets_sha256`. Copy full Git SHA, stable SemVer and immutable OCI digests; do not infer them from tags or an image config ID.

For a completed promotion choose `target: previous`; the target contract hash must equal the predecessor's recorded hash. For a failed/interrupted deployment with pending state choose `target: current`; bind the pending candidate explicitly and restore the last successful current receipt. A never-completed pending image is NEVER a rollback target or retained predecessor. Supply the selected target's full source SHA to the protected `rollback.yml` dispatch and use its corresponding owner-reviewed activation contract. Runtime env/APP_KEY file, DB CA, database connection, selected host, project and EBS upload mount remain the same persistent inputs; recovery cannot relocate them. A missing historical Compose/configuration hash fails closed and requires an explicit manual plan.

The read-only preflight checks the existing environment before the privileged job is scheduled, then rechecks its numeric/node IDs after human approval. It verifies the signed JWT and uses that SAME token to assume the separate role. The host acquires the shared deployment lock, matches all current/previous/pending identities, verifies retained image/asset provenance, drains worker/scheduler with 90-second grace, starts N-1 web, requires verified HTTPS readiness, reloads one worker and one scheduler, checks processes again, and verifies liveness plus the actual retained public asset manifest over HTTPS. It does not invoke `migrate`, any schema rollback, format/chown uploads, remove volumes or write secrets. Private runtime input bytes must remain unchanged before a successful receipt is committed.

The completed receipt retains original release/configuration identity, rollback-from identity, request hash, UTC start/completion times and operation. Retrying the exact completed request performs read-only health/process/smoke checks; it never migrates or restarts services. A failure preserves the former completed receipts and a pending rollback phase, stops the unverified candidate and returns nonzero. Inspect that phase and the known SSM command UUID/host before taking any further action; never blindly resend a timed-out command. Interrupted rollback is intentionally not cleared automatically: recover the private pending state only under a separately reviewed manual plan after establishing the actual running containers, data/schema compatibility and retained digests. Preserve database/uploads/secrets; do not delete a volume to repair a release receipt. Only after those checks approve a concrete recovery and repeat the post-recovery smoke.

The disposable CI builds each of two distinct Git sources once, retains and verifies true OCI manifests locally, promotes N then N+1, restores N without rebuilding, and exercises recovery after a real database readiness failure. It checks HTTPS assets, workers/scheduler, read-only retry, persistent SQL/upload data and unchanged private APP_KEY/runtime inputs, and removes owned disposable resources. Only a sanitized JSON result is uploaded; OCI archives, SQL and secrets stay on the runner. This proves the local Docker host path, not real AWS/SSM, production cutover, authentication session roundtrip, zero downtime, RTO/RPO or reversible database effects. The broader auth/session upgrade rehearsal belongs to issue #38.
