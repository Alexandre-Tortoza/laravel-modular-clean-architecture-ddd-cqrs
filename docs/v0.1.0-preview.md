## Requirements and first use

- Recommended local path: Git, POSIX shell/WSL2, Docker daemon access and Compose
  v2; Sail supplies PHP 8.4, Node 22 and PostgreSQL 16. Host PHP/Composer/npm are
  unnecessary for that path.
- Host alternative: PHP 8.4.1+, Composer 2.8+, Node 22.18+ in the 22.x series,
  npm and SQLite PDO; inspect `composer check-platform-reqs`. PHP 8.5 is the
  primary CI version, with actual minimum-PHP acceptance at 8.4.1.
- Locked framework/tool versions include Laravel 13.35.0, Fortify 1.41.0,
  Inertia Laravel 3.5.1 and Pest 5.3.1. Keep both lockfiles; do not run dependency
  updates to adopt the template.
- Production reference: separate pinned PHP 8.5.10 FPM and Nginx 1.30.5 containers,
  Compose 2.30+ for raw runtime env files. AWS remains optional; Redis/Valkey are
  off by default and database cache/session/queue remain the initial choices.

Follow the [README](../README.md) and [development guide](development.md), using a
reviewed branch while remote dev/main await owner integration. Bootstrap/setup
preserve existing configuration and APP_KEY; ordinary seeding creates no demo
accounts. Provision the first user through the interactive, hidden-password
command. The account initially needs email verification before verified routes;
the local log mailer keeps the requested verification message in private logs.
Demo data is an explicit disposable local/testing opt-in. No published
release download or active “Use this template” setting is assumed here.

## Compatibility, upgrade and operational limits

`v0.1.0` is an initial **template** version. Derived applications own independent
versions and history; template creation does not propagate upstream updates.
Before 1.0, review each minor upgrade's compatibility and migration notes. Adopt
changes in an application branch, test them against representative disposable
data and preserve APP_KEY, schema history, runtime secrets and uploads. Do not
copy the template's database over application data or replay existing migrations.

Native demo/first-account changes are deliberate: public registration is disabled,
standard setup/seeding creates no credentials, and hidden interactive first-user
provisioning replaces reliance on demo accounts. Generated placeholders and pending
tests need application implementation. Authentication, invitations and mail require
a derived application's own approved transport and operational configuration.

For application releases, require matching retained PHP/Nginx digests/assets,
reviewed expand/contract N/N-1 schema and queue compatibility, one migration process,
90-second worker grace, one scheduler and trusted HTTPS readiness. Rollback
restores retained code/configuration, not reversed DDL, deleted data or external
effects. The deploy executor checks env ownership/mode, approved paths/public
hashes/EBS binding and HTTPS readiness; its background-process gate checks running,
non-unhealthy containers, not actual queue consumption or PHP-child readiness.
It does not compare runtime secret bytes before/after promotion. Stable secret
inputs remain an operator precondition. Rollback fingerprints compare its inputs
only before/after that operation, not secret bytes against historical releases. After the receipt, the operator must
perform representative authenticated/data/assets/queue/scheduler smoke before
accepting the rollout. Native disposable cycles provide those stronger assertions
only on their owned fixtures. Read [deployment](deployment.md) and
[releases/recovery](releases.md).

One EC2/retained EBS stack and Single-AZ RDS are failure domains. The fixtures
prove disposable local runtime/upgrade and logical backup behavior; they do not
prove actual AWS IAM/SSM, RDS snapshot/PITR, EBS restore, public CA/DNS activation,
production RPO/RTO, staging cutover or zero downtime. Owner-selected regions,
capacity, costs, recovery objectives and private secret/certificate authorities
remain explicit decisions. Optional Valkey has one primary, no failover; database
drivers remain defaults. Benchmark evidence does not switch the production server.
Business flags/Pennant are deferred, not implemented.

The repository's MIT license retains the original starter notice and the current
author notice. Third-party dependencies keep their own licenses/notices; the
inventory in the snapshot reports metadata, not a blanket license certificate.
Some optional npm platform packages have no lockfile license field; do not infer
one or redistribute dependency binaries without checking their source/version
and required notices. Preserve installed/distributed dependency notices.
